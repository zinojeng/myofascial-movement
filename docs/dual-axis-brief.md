# 雙軸評價規格書

這份文件補充 [`curation-brief.md`](curation-brief.md)，處理一件原始規格沒處理好的事：

> **不要只用「有沒有論文」來挑影片與評價影片。**

---

## 1. 問題在哪

第一版網站只有一個分數：科學證據強弱（證據充分／中等／有限／互斥）。
這適合評估**科學主張**，但不適合評價**一位好教練**。

筋膜訓練有大量知識本來就不是研究論文能直接回答的：

- 這個動作怎麼教比較容易成功？
- 學員最常錯在哪裡？
- 壓力太大、太小會如何？
- 某個動作無感時怎麼退階？
- 不同身體條件如何選替代動作？
- 實際課表怎麼串起來？

這些是**實務知識（practice-based knowledge）**，來自教練、物理治療師與長期實作者的累積。
用「沒有 PubMed 引用」把它們排除，等於把學習者最需要的部分丟掉。

真正該避免的不是經驗性內容，而是：

> **把個人經驗包裝成已被科學證明的普遍定律。**

## 2. 兩個軸，各自獨立

### 軸一：科學證據可信度 `evidence_grade`

| id | 顯示 | 用在什麼情況 |
|---|---|---|
| `strong` | 證據較充分 | 多篇一致的統合分析／系統性回顧 |
| `moderate` | 證據中等 | 有統合分析但效果量小或異質性高 |
| `limited` | 證據有限 | 只有少數小型試驗，或只有短期終點 |
| `expert-consensus` | 專家共識 | 沒有直接試驗，但專業社群做法高度一致 |
| `experience` | 經驗性主張 | 來自長期教學觀察，尚無研究檢驗 |
| `contested` | 存在爭議 | 研究結論彼此衝突，或機轉說法被反證 |

`expert-consensus` 與 `experience` **不是「比較弱的科學」**，它們是不同種類的知識。
把它們標成 `limited` 會誤導讀者以為有人做過研究但結果不好。

### 軸二：實務教學價值 `practical_value`

| id | 顯示 |
|---|---|
| `very-high` | 非常高 |
| `high` | 高 |
| `medium` | 中等 |
| `limited` | 有限 |

一支影片完全可以是：

> 科學引用：有限　·　動作教學：非常清楚　·　安全提醒：完整　·　實務價值：非常高

這樣就不會出現「因為沒有研究，所以這支教學影片沒有價值」，
也不會出現「因為教練很有名，所以他說的所有機轉都是正確的」。

## 3. 怎麼判斷實務教學價值

**不要看訂閱數或觀看數。** 看這八件事：

1. **是否說清楚適用對象** — 好的教練會說適合誰、不適合誰、初學者從哪開始、
   有疼痛時如何調整。不好的內容會說「每個人都應該做這個動作」。
2. **是否提供進階與退階** — 例如臀部按摩球：靠牆（初階）→ 坐地面（中階）→
   加髖旋轉（進階）→ 疼痛敏感者用較軟工具。能分層通常代表真的教過很多人。
3. **是否解釋常見錯誤** — 滾太快、憋氣、壓在骨頭或神經敏感區、
   為追求痛感而過度施壓、做完沒有接主動活動。
4. **是否避免過度承諾** — 好的專業人士會用「可能」「有些人」「短期」
   「作為其中一種選擇」「需要配合主動訓練」「症狀持續應接受評估」。
5. **是否把「感覺」與「結構改變」分開** — 可以說「做完可能覺得比較鬆」，
   不能直接跳到「所以筋膜被拉長了／沾黏被打散了」。
6. **是否有安全界線** — 不滾壓頸前、避開明顯腫脹處、急性外傷與感染要謹慎、
   出現麻木電擊感要停、不能取代必要的醫療評估。
7. **是否說明「為什麼這樣安排」** — 為什麼先放鬆再活動、為什麼活動度後要加控制、
   為什麼最後加負荷、為什麼不是每個部位都滾五分鐘。
8. **是否允許個體差異** — 承認骨骼結構、活動範圍、疼痛敏感度、運動需求都不同，
   同一個提示不一定適合所有人。

## 4. 內容角色 `source_type`（可複選）

| id | 顯示 | 意義 |
|---|---|---|
| `science` | 科學基礎 | 解釋解剖、生理或研究 |
| `expert-view` | 專家觀點 | 專業人士對現有知識的整理 |
| `coach` | 教練經驗 | 來自長期教學與實務觀察 |
| `clinical` | 臨床經驗 | 來自治療或復健工作 |
| `demo` | 動作示範 | 主要用來跟練 |
| `program` | 課表設計 | 教頻率、順序與負荷安排 |
| `contested-view` | 爭議觀點 | 有實務支持，但科學解釋仍有爭議 |
| `safety` | 安全提醒 | 特別處理禁忌與風險 |

一支影片可以同時有兩三個，例如 `["coach", "demo", "program"]`。
**陣列第一個是「主要角色」**，內容配比就是照它計算的。

## 5. 目標內容配比

| 類型 | 目標 |
|---|---|
| 科學與理論（`science` + `expert-view`） | 20% |
| 教練／治療師實務（`coach` + `clinical`） | 40% |
| 純動作示範（`demo`） | 30% |
| 爭議與不同觀點（`contested-view`） | 10% |

教練型內容可以是整門課的主體，因為使用者真正需要的是「怎麼做」。
科學證據的角色是：限制不合理宣稱、區分已知與推測、補充安全界線、
避免把單一方法神化、說明還有哪些替代方案。

`make audit` 會檢查配比並在偏離超過 ±10% 時**警告**（不是錯誤）。
**誠實標註優先於湊配比。** 警告是關於策展現況的真實資訊，不是要你回頭改標籤。

## 6. 每支影片的新欄位

```jsonc
{
  "title": "…", "channel": "…", "url": "…", "duration": "12:30",

  "source_type": ["coach", "demo"],      // 必填，1–3 個，第一個是主要角色
  "practical_value": "high",             // 必填

  "coach_takeaway": "以可控制的壓力停留，再加入踝關節主動活動，而不是快速來回滾動。",
  "claim_boundary": "影片把活動度改善解釋為筋膜沾黏被打開，此機轉說法缺乏直接證據。",
  "safety": ["避免直接壓迫腓骨頭附近", "出現麻木或電擊感應立即停止"]
}
```

- `coach_takeaway` — 實務操作重點。**不要重複 `why`**（那是選片理由）。
- `claim_boundary` — **只在影片有過度宣稱時才加。** 沒有就不要放這個欄位，
  不要為了填滿而硬找碴。
- `safety` — **只在該動作有明確禁區或停止條件時才加。**
- `creator_background` 不寫在影片上，改由 `course/data/channels.json` 依頻道提供。

### 應避免的說法（出現就要寫進 `claim_boundary`）

一次就能把沾黏完全打開 · 這個動作能把骨盆永久調正 · 所有下背痛都是筋膜造成 ·
只要按這個點就能治療坐骨神經痛 · 滾筒可以排毒 · 疼痛越強效果越好 ·
把緊繃的筋膜拉長 · 排出乳酸

## 7. 每個單元的四段結構

網站上每個單元固定分成四段，對應到資料裡的四個地方：

| 段落 | 資料來源 |
|---|---|
| **一、目前科學怎麼說** | `oe-*.json` 的 `summary`（既有） |
| **二、教練怎麼做** | 單元的 `coach_practice`（**這次新增**） |
| **三、實際跟練** | `drills` 陣列（既有） |
| **四、你要觀察什麼** | 單元的 `assessment`（既有，UI 標題改成這個） |

`coach_practice` 寫 120–250 字的**實務策略**，不是理論：
找敏感區域的順序、壓力怎麼拿捏、常見錯誤、無感時怎麼進階、太痛時怎麼退階、
如何串進當天的訓練。

這樣教練經驗就不是被排除，而是被放在正確的位置。

## 8. 字幕

`make meta` 會把每支影片的字幕軌記進 `video-meta.json`（`subs` 人工／`auto_subs` 自動，
只留 en/zh）。實測結果：**124 支裡 45 支完全沒有字幕，幾乎全是中文頻道。**

英文專業頻道普遍有英文字幕，YouTube 還能自動翻成繁中，所以每個單元加一支
英文主課是**可及性**補強。框架原生支援多語言主課（`alt-lessons-*.json`），
網站會在主課卡片上出現語言切換分頁。

已實測確認有英文字幕的頻道：Physiotutors、E3 Rehab、Tom Merrick、[P]rehab、
The Movement System、Squat University、Precision Movement、Sports Injury Physio、
Hospital for Special Surgery、FitnessFAQs、Jeff Nippard。

```bash
uv run python src/build/ytsearch.py subs <videoId> [<videoId> ...]
```

> YouTube 會對逐支影片的抓取啟動 bot 偵測（搜尋端點不受影響）。
> 被擋時 `subs` 會回報 ✗，這不代表影片沒有字幕——等限制解除後跑
> `make meta ARGS=--refresh` 統一補齊，再看稽核報告。
